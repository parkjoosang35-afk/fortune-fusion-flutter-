## 0. 한눈에 보는 서비스 개념

**궁합지도("인연지도")**는 "나를 중심으로, 지금까지 궁합을 본 모든 사람이 별이 되어
궤도를 도는" 메인 홈 지도입니다. 귀인지도처럼 호스트/게스트가 엄격히 분리된 1회성
여정이 아니라, **로그인한 회원 한 명이 반복적으로 여러 사람과의 궁합을 쌓아가는**
개인 기록형 서비스입니다.

- **나(로그인 회원)**: 지도의 중심. 상대방을 "직접 입력"하거나 "초대장"을 보내서
  궁합을 본다. 궁합을 볼 때마다 상대방이 지도 위에 별로 추가/갱신된다. 상세 보고서는
  100 복주머니로 해금한다(귀인지도의 "10장 심층 풀이"와 유사한 유료 전환점).
- **상대방(초대받은 사람, 비로그인 가능)**: 초대 링크를 열고 자신의 생년월일만
  입력하면 무료 등급(8개 분야 간단 등급)을 볼 수 있다. 상세 보고서 해금은 **초대한
  사람만** 할 수 있다(상대방에게는 결제/해금 동선이 전혀 없음).
- **동일 인물 1회 등록 원칙**: 같은 사람과 궁합을 여러 번 봐도 지도 위의 별은
  1개만 존재한다 — 가장 최근 점수로 위치만 갱신되고, 과거 이력은 그 별의 "히스토리"로
  쌓인다(점수 자체는 각 분석마다 저장 후 불변).

```
[나] 홈 「인연지도」 진입 ─┬─ "✦ 새 궁합 시작하기"(직접 입력) ──┐
                         │                                    │
                         └─ "궁합 초대장 보내기"(카카오 공유) ──┤
                                                                ▼
                                                 분야 선택(8종) → 세부 선택
                                                                │
                                   ┌────────────────────────────┤
                                   ▼                            ▼
                      [직접 입력] 상대방 정보 직접 입력   [초대장] 카카오 공유
                      → 즉시 결과 생성                    → 상대방이 링크 열어
                                   │                        본인 생년월일만 입력
                                   │                            │
                                   └──────────┬─────────────────┘
                                              ▼
                              결과 생성 → 지도에 별 추가/갱신
                                              │
                              [나] 별 탭 → RelationSheet(오행 관계·점수·해석)
                                              │
                              → 상세 보고서 해금(100 복주머니, 나만 가능)
                                              │
                              → 결과 이미지 저장 / 궁합스토리(전체 목록) 관리
```

**빈 자리(인연 슬롯) 8개**: 아직 안 채워진 "흔히 있는 관계"(배우자/엄마/연인/절친/
아빠/동료/형제자매/썸)를 점선 별로 미리 지도에 보여줘서, 사용자가 "누구와 궁합을
볼지" 힌트를 얻게 한다. 실제 인물이 늘어날 때마다 슬롯이 하나씩 사라진다(§5 참고).

## 1. 대분류(8개) · 세부 카테고리 체계

| id | 이름 | 한자 | 세부 카테고리 수 | 한 줄 설명 |
|---|---|---|---|---|
| `love` | 연애 궁합 | 戀 | 7개 | 설렘에서 깊은 사랑까지, 두 마음의 온도 |
| `marriage` | 결혼 궁합 | 婚 | 7개 | 함께 꾸려갈 삶의 결과 흐름 |
| `intimacy` | 속궁합 | 親 | 6개 | 몸과 마음이 가까워지는 방식 |
| `persona` | 성격 궁합 | 性 | 7개 | 기질과 대화가 맞물리는 방식 |
| `wealth` | 재물 궁합 | 財 | 6개 | 돈을 대하는 두 사람의 태도 |
| `business` | 사업 궁합 | 業 | 7개 | 함께 일할 때 드러나는 합 |
| `friend` | 친구 궁합 | 友 | 7개 | 오래 곁에 둘 인연의 결 |
| `family` | 가족 궁합 | 家 | 7개 | 가장 가까운 사이의 이해 |

- 홈 화면 2열 타일에서는 "OO 궁합" 접미사를 뗀 축약명(연애/결혼/속궁합/성격/재물/
  사업/친구/가족)을 씁니다.
- 세부 카테고리(예: 연애 궁합 → 썸 궁합/연애 궁합/짝사랑 궁합/재회 궁합/장거리 연애
  궁합/애정표현 궁합/이상형 궁합) 전체 54종은 `gunghap_data.dart`의 `ghSubs` 참고 —
  디자인 시안에서 전부 나열할 필요는 없지만, "세부 카테고리 선택" 화면(아래 §3-2)의
  리스트형 UI 레이아웃만 잡아 주시면 됩니다.
- 보고서 9개 장(I~IX, 두 사람의 관계 종합 해석 ~ 관계 발전을 위한 조언)은 현재
  화면에 직접 노출되지 않고 상세 보고서 내부 텍스트 구성 기준으로만 쓰입니다.

## 2. 화면 전체 목록 (실제 라우트/네비게이션 기준)

궁합지도는 named route가 아니라 대부분 `Navigator.push(MaterialPageRoute(...))`로
직접 이동합니다. 메인 홈만 전체보기 카드에서 `MaterialPageRoute`로 진입하고, 예외적으로
`/gunghap/story`(마이페이지에서 진입)와 `/gh/{token}`(카카오 공유 딥링크) 2개만
named route입니다.

| 진입 경로 | 화면 파일 | 역할 |
|---|---|---|
| 홈 "궁합지도" 카드 → `GunghapHomeScreen()` | `gunghap_home_screen.dart` | **메인 홈 「인연지도」** — 다인 궤도 지도(DestinyMap) + 분야 칩 + CTA 2개 + 대분류 8타일 + 최근 궁합 |
| 홈에서 "✦ 궁합 시작하기" / "궁합 초대장 보내기" | `gunghap_major_screen.dart` | **대분류 선택** — 8개 카드 그리드, 고르면 0.26초 선택 애니메이션 후 자동 전환 |
| 대분류 선택 후 | `gunghap_sub_screen.dart` | **세부 카테고리 선택** — 상단 대분류 전환 칩 + 세부 목록(번호 매김 카드), 하단 CTA가 method(`direct`/`invite`)에 따라 분기 |
| method=`direct` | `gunghap_direct_input_screen.dart` | **직접 입력** — 상대방 이름/생년월일/양음력/시간/성별 입력, "궁합 확인하기" 누르면 즉시 결과 생성 |
| method=`invite` | `gunghap_invite_screen.dart` | **초대장 생성** — 내 사주로만 초대장 생성(상대방 정보 입력 없음), 생성 직후 자동 카카오 공유 시트, "참여 현황 확인하기"로 폴링 |
| (딥링크 `/gh/{token}`) | `gunghap_guest_input_screen.dart` | **게스트 참여** — 비로그인으로 도달, 본인 생년월일만 입력(로그인 불필요). 초대 상태 4종(pending/completed/cancelled/expired) 분기 처리 |
| 게스트 제출 성공 후 | `gunghap_guest_result_screen.dart` | **게스트 본인 결과** — StarMap(2인) + 등급 요약 + 8개 분야 등급(무료). 해금/상세보기 버튼 없음. "나도 궁합지도 만들기" CTA만 |
| 초대자가 "참여 현황 확인" 성공 시 / 직접입력 성공 시 / 히스토리 탭 시 | `gunghap_result_screen.dart` | **결과 화면(소유자 전용)** — StarMap(2인) + 등급 요약 + 8개(or 1개) 분야 등급 + 상세 보고서 해금(100 복주머니) + 해금 후 7단계 상세 + 결과 이미지 저장 |
| 마이페이지 → `/gunghap/story` (named route) | `gunghap_story_screen.dart` | **궁합스토리(전체 목록)** — DIRECT+INVITE 통합 최신순 목록, 삭제(소프트), 당겨서 새로고침 |
| 홈 상단 "◈ 내 궁합" | → `GunghapStoryScreen()` push | 위와 동일 화면 재사용 |
| (현재 코드상 도달 경로 없음 — 죽은 화면) | `gunghap_coming_soon_screen.dart` | 과거 "준비 중" 플레이스홀더. 현재 어디서도 push되지 않음(§4 참고) |

### 참고: 별개 기능인 "궁합(C그룹)" — 디자인 대상 아님

`lib/features/compatibility/`(`compatibility_input_screen.dart`,
`compatibility_result_screen.dart`, 라우트 `/compatibility/input`,
`/compatibility/result`)는 **궁합지도와 전혀 다른, 별도로 살아있는 기능**입니다.
애정운/우정운/사업운/가족운 4종을 0~100점 수치로 보여주는 단순 궁합 계산기로,
홈 배너 캐러셀과 "전체보기" 화면의 구(舊) 카테고리 항목에서 연결됩니다. 죽은
코드가 아니라 **현재도 운영 중인 다른 서비스**이므로 이번 궁합지도 디자인
작업과는 무관하게 그대로 둡니다(헷갈리지 않도록 참고만 해주세요).

## 3. 핵심 화면 상세 (디자인 참고용)

### 3-1. 메인 홈 「인연지도」 (`GunghapHomeScreen`)

위에서 아래 순서:

1. **상단 배지**: `✦ DESTINY MAP · 因緣之圖` (금색 점 + 모노스페이스 라벨)
2. **헤드라인** — 인연 수에 따라 3단계로 문구가 바뀜:
   - 0명: 코치 말풍선 "빈 자리를 눌러보세요" + "빈 자리에 인연의 / 별을 띄워보세요"
   - 1~7명: "인연지도를 / 조금 더 채워볼까요"
   - 8명 이상(슬롯 모두 소멸): "나를 중심으로 도는 / 인연의 별들"
3. **인연지도 그래픽(DestinyMap)** — 화면 폭의 78%, 정사각형. 아래 §5 참고.
   - 로딩 중: 궤도+나만 그려진 빈 지도로 자연스럽게 표현(스피너 없음)
   - 진짜 네트워크 오류일 때만 "별을 불러오지 못했어요 / 다시 시도" 문구로 대체
   - 비로그인/로그인 직후 토큰 미반영 상태(UNAUTHORIZED)는 오류로 취급하지 않고
     빈 자리 8개가 채워진 지도를 그대로 보여줌
4. 안내 문구: "안쪽 궤도일수록 궁합 점수가 높아요 · 별을 누르면 궁합 관계가 열려요"
5. **분야 칩(가로 스크롤)**: 전체 + 8개 대분류. 선택하면 비선택 별들이 흐려짐
   (opacity 0.18) — 지도 자체 필터링, 화면 전환 없음
6. **CTA 2단**:
   - Primary(XL, 금색, 빛 스침 애니메이션 3.6초 주기): "✦ 첫 궁합 시작하기"(인연 0명)
     / "✦ 새 궁합 시작하기"(1명 이상) → `GunghapMajorScreen(method:'direct')`
   - Secondary(MD): "✉ 궁합 초대장 보내기" → `GunghapMajorScreen(method:'invite')`
7. **대분류 8타일(2열 그리드)**: 아이콘(별자리 스타일 CatIcon) + 이름 + "N가지"(세부
   개수). 탭하면 분야 선택 화면을 건너뛰고 바로 세부 카테고리 화면으로 이동
8. **최근 살펴본 궁합(최대 2건)**: 서버 `GET /my-results`에서 최신 2건만 미리보기.
   비어 있으면 섹션 자체를 숨김(더미 데이터 없음). "내 궁합 관리 ›" → 궁합스토리 전체
9. 하단 공용 바텀 네비게이션(`MainBottomNavBar`, currentIndex 0)

### 3-2. 대분류 선택 (`GunghapMajorScreen`)

- 2열 그리드, 8개 카드(아이콘 + 이름 + 설명 2줄 + 체크 표시)
- 홈 2열 타일에서 바로 들어온 경우(`skipToSub`)는 이 화면 자체를 건너뛰고 빈
  배경만 잠깐 보여준 뒤 바로 세부 화면으로 전환(깜빡임 방지용 트랜지션 대기)
- 카드 선택 시 0.26초 지연 후 세부 카테고리 화면으로 자동 이동

### 3-3. 세부 카테고리 선택 (`GunghapSubScreen`)

- 상단: 대분류 가로 스크롤 전환 칩(다른 대분류로 바로 갈아탈 수 있음)
- 선택한 대분류 아이콘 + 한자 + "N TYPES" + "세부 궁합을 골라 주세요"
- 세부 목록: 번호(01, 02…) + 이름 + 설명 1줄, 라디오 형태 선택
- 하단 CTA: 미선택 시 비활성("세부 궁합을 선택해 주세요"), 선택 시 "{세부명}으로
  진행" → **method가 `direct`면 `GunghapDirectInputScreen`, `invite`면 기존
  `GunghapInviteScreen`으로 분기**

### 3-4. 직접 입력 (`GunghapDirectInputScreen`)

- STEP 2/3 — 상대방 이름(별칭, 20자)/생년월일(년·월·일 3칸)/양력·음력·음력(윤달)
  3분기 칩/태어난 시간(모름 체크 가능)/성별(여성·남성 칩) 입력
- "궁합 확인하기" → 즉시 서버가 결과 생성 → `GunghapResultScreen`으로 이동(초대장
  생성 없음, 상대방에게 어떤 알림도 가지 않음)
- 비로그인이면 입력 폼 진입 자체는 가능하나 제출 시 로그인 화면으로 이동

### 3-5. 초대장 생성 (`GunghapInviteScreen`)

- STEP 2 — **상대방 생년월일 입력 필드가 전혀 없음**(귀인지도와 동일한 "발송자가
  상대방 정보를 몰라도 되는 구조" 원칙)
- StarMap(2인용, 미생성 시 "나" vs "?" 플레이스홀더, 생성 후 "나" vs "초대받은 사람")
- "내 사주로 초대장 만들기" → 생성 성공 시 자동으로 카카오톡 공유 시트 오픈(method가
  `invite`일 때만; `direct`에서 우회 진입한 경우는 수동 공유 버튼만 노출)
- 생성 후: "카카오톡으로 공유하기" / "다른 방법으로 공유하기" / "참여 현황 확인하기"

### 3-6. 게스트 참여 입력 (`GunghapGuestInputScreen`, `/gh/{token}`)

  - **cancelled**: "🚫 초대한 사람이 링크를 중단했어요"
  - **expired**: "⌛ 초대 링크가 만료됐어요 (7일 경과)"

### 3-7. 게스트 본인 결과 (`GunghapGuestResultScreen`)

  있어요" 안내만 — **해금 버튼/상세 열람 동선 전혀 없음**(권한 원칙)
- 하단 CTA: "나도 궁합지도 만들기" → 홈으로 전체 스택 리셋 이동

### 3-8. 결과 화면(소유자 전용, `GunghapResultScreen`)

### 3-10. 별 탭 → RelationSheet (바텀시트, 모든 화면 공통 아님 — 홈 전용)

홈 `DestinyMap`에서 실제 별(사람)을 탭하면 뜨는 바텀시트(최대 높이 86%):

1. 헤더: `RELATION · {분야 한자}` / "나 ✦ {이름}" · 분야 칩 · ✕
2. **점수 카드**: 좌측 원형 게이지(64px, 40~100→0~100%) + 점수, 우측 "{세부} 점수" /
   "{밴드명} 사이" / "점수가 높을수록 지도에서 나와 가까워요"

3. **오행 관계도**: [나(일간+오행 한자, 원형)] — {관계 한자 1글자 + 화살표 + 한자
   2글자} — [상대(일간+오행 한자, 원형)], 하단에 "{관계명} · {설명}" 칩

4. **두 사람의 관계**: 해석 본문 1문단
5. **강점 / 살펴볼 부분**: 2열 카드(✦ 관계의 강점 / ◇ 살펴볼 부분, 각 bullet 리스트)
6. **"{이름}님과 본 궁합 · n"**: 히스토리 목록(세부명 + REPORT 뱃지(구매분) + 점수 +
   날짜 + ›) — 탭하면 해당 결과 화면으로 이동
7. 근거 문구: "거리는 궁합 점수(40~100), 선은 두 사람의 일간 오행 관계(FACT)로
   정해져요. 저장된 점수는 다시 열어도 바뀌지 않아요."
8. Footer: "＋ 궁합 추가"(secondary, 분야 선택 화면으로) / "{분야} 궁합 결과 보기"
   (primary, 결과 화면으로)

### 3-11. 빈 자리 탭 → SlotSheet (바텀시트, 홈 전용)

홈 `DestinyMap`에서 빈 자리(점선 별)를 탭하면 뜨는 바텀시트:

1. 헤더: `EMPTY SEAT · {분야 한자}` · ✕

## 5. 인연지도(DestinyMap) 좌표/궤도 규칙 — **디자인 변경 시 반드시 참고**

이 섹션은 `MAP_HOME_SPEC.md`(디자인 핸드오프)에 명시된 수치이자 현재 코드
(`destiny_map.dart`)가 실제로 구현한 값입니다. 디자인을 새로 입히더라도 아래 "점수 →
거리" 계산 로직과 데이터 계약은 그대로 유지되어야 하므로, 시안에서 각도/거리를 임의로
다시 정의하지 말고 이 규칙 위에서 비주얼만 다시 그려주시면 됩니다.

- **좌표계**: viewBox 360×360, 중심 `(180, 180)` = "나"
- **점수 → 거리(연속값)**: `r = 46 + 105 × (100 − score) / 60` (score는 40~100
  클램프 — 100점일수록 중심에 가깝고, 40점일수록 바깥쪽)
- **점수 구간 눈금(시각적 참고선 6개, 실제 배치는 연속값)**: 90 / 82 / 74 / 66 /
  58 / 40
- **각도(등록순서 기반 황금각 고정)**: `angle_deg = (등록순서 × 137.508° + 18°) mod
  360` — 점수가 바뀌어도 방향은 유지되고 거리만 이동(서버가 계산해 내려줌)
- **공전**: 전체 별이 동일 속도로 공전(약 150초/회전, vivid 모드는 속도 계수 .55배
  더 빠름) — 궤도 그룹별로 약간 다른 주기(안쪽 궤도일수록 빠름: `(70 + orbit×26) ×
  speed`초/회전)
- **별 탭 시**: 공전 정지 → RelationSheet가 슬라이드업(400ms)
- **별 크기**: 안쪽 궤도(0~1)일수록 크게(반지름 4.4), 바깥쪽(4~5)일수록 작게(3.2)
  + 글로우(반지름×4.2)
- **별 라벨**: 위쪽에 상대 일간 한자(1글자), 아래쪽에 이름, 그 아래 점수(모노스페이스)
  — 공전해도 항상 수평 유지(역회전 보정)
- **연결선**: 나→별, 금색에서 오행색으로 그라데이션, 기본 점선 느낌·선택 시 실선
  두께 증가
- **바깥 링**: 12지지 + 눈금 72개, 260초×speed 주기로 느리게 회전
- **배경**: 성운(중심 바이올렛 글로우) + 별가루 70개(트윙클 애니메이션) + (vivid
  모드 한정) 유성 3개가 정해진 지연/주기로 사선으로 흐름
- **점수 불변 원칙**: 지도 위 점수는 "그 사람과 본 가장 최근 분석"의 엔진 점수를
  그대로 표시 — 재계산하지 않음. 동일 인물과 새 궁합을 보면 기존 별이 삭제되지 않고
  "위치만 갱신"됨(과거 이력은 히스토리로 보존)

### 빈 자리(인연 슬롯) 8개 고정 명세

| id | 라벨 | 연결 대분류 | 추천 문구 | 가상 점수(거리 계산용) | 고정 각도 |
|---|---|---|---|---|---|
| `spouse` | 배우자 | 결혼 | 부부 · 결혼 · 생활 | 92 | 345° |
| `mom` | 엄마 | 가족 | 어머니·자녀 · 가족 생활 | 88 | 210° |
| `lover` | 연인 | 연애 | 연애 · 썸 · 애정표현 | 80 | 300° |
| `bestfriend` | 절친 | 친구 | 절친 · 여행 · 취미 | 76 | 120° |
| `dad` | 아빠 | 가족 | 아버지·자녀 | 70 | 165° |
| `colleague` | 동료 | 사업 | 직장 동료 · 업무 | 64 | 30° |
| `sibling` | 형제·자매 | 가족 | 형제·자매 | 58 | 75° |
| `crush` | 썸 | 연애 | 썸 · 짝사랑 | 52 | 255° |

- 슬롯은 공전하지 않음(고정 위치) — 점선 원 + '+' + 라벨
- 실제 인물 수가 늘어날수록 **목록 뒤에서부터** 슬롯이 하나씩 사라짐(간단한 근사
  규칙 — "슬롯-인물 매핑" 전용 DB 컬럼은 아직 없음)
- 같은 이름의 실제 별이 생겨도 반드시 그 슬롯부터 없어지는 것은 아니며(현재는
  단순 개수 기준), 추후 "슬롯 ↔ 실제 인물" 매칭을 정교화할 여지가 있음(디자인
  변경과 무관한 백엔드 영역)

## 7. 데이터 구조 (디자인 시 참고 — 실제 값 예시)

```
MapPerson {
  personKey      // 동일 인물 판정 키(person_id 기준, 서버 계산)
  name           // 상대 이름
  element        // 상대 일간 오행 한자(木火土金水)
  stem           // 상대 일간 한자(甲..癸)
  score          // 저장 후 불변 — 가장 최근 분석의 엔진 점수(40~100)
  angleDeg       // 등록순서 기반 황금각 고정 좌표
  majorId        // 이 인물과 가장 최근에 본 분야(연애/결혼/... 중 1개, nullable)
  resultId       // 최신 궁합 결과 id(RelationSheet·결과보기에 사용)
  history[]      // { resultId, sub(세부명), date, paid(상세보고서 구매여부), score }
}

MapMe { stem, element }  // 나의 일간/오행만(생년월일 자체는 노출 안 함)
```

- 호스트(나) 1명이 여러 `MapPerson`을 가짐 — 귀인지도처럼 "지도 1개 = 소유자 1명"
  구조와 동일하되, 궁합지도는 관계유형 체계(6종)가 아니라 **점수(0~100) + 오행
  관계(5종: 비화/상생out/상생in/상극out/상극in)**로 관계를 표현
- 오행 관계 FACT(`relation.key/short/hanja/ko/label/arrow`)는 서버가 두 사람의
  실제 일간으로 계산 — 클라이언트 하드코딩 없음

## 8. 변경 금지 / 재사용해야 하는 로직 (디자인 변경과 무관하게 유지)

- 점수 불변 원칙(저장된 점수는 재조회해도 바뀌지 않음), 동일 인물 1회 등록(person_id)
- 황금각 좌표 공식, 연속 거리 공식(§5) — 서버가 계산해 내려주는 값 그대로 사용
- 상세 보고서 100 복주머니 해금(소유자 전용, 멱등), 환불 시(`refunded:true`) 안내
  배너 노출
- DIRECT(초대장 없이 직접 입력) vs INVITE(초대장 발송) 두 경로는 끝까지 독립 —
  DIRECT는 상대방에게 어떤 알림도 가지 않고, `ownerName`이 항상 null로 저장됨
  (상대방 이름 표기는 항상 `guestName` 필드 사용)
- 게스트(초대받은 사람) 화면에는 해금/결제 동선을 절대 추가하지 않음(권한 원칙)
- 초대 링크 상태 4종(pending/completed/cancelled/expired) 분기 처리
- `requestKey` 멱등성(직접 입력 "확인" 버튼 재시도 시 동일 키 재사용, 성공/새 조회
  시에만 새로 발급)

## 10. 디자이너에게 드리는 요청

1. 위 2장의 **화면 목록** 순서대로 시안을 만들어 주세요(§2 표 기준 — `compatibility`
   계열은 완전히 다른 서비스이니 제외해 주세요).
2. **메인 홈(§3-1)의 인연지도 그래픽**이 가장 중요합니다 — §5의 궤도/각도/빈자리
   규칙을 참고해, "점수가 높을수록 중심에 가깝다"는 규칙과 "빈 자리 8개" 개념만
   유지해 주시면 비주얼 스타일(색감, 별 모양, 배경 연출 등)은 자유롭게 새로 제안해
   주셔도 됩니다.
3. **RelationSheet(§3-10)와 SlotSheet(§3-11)** — 바텀시트 2종의 구성 요소(헤더/
   점수카드/오행관계도/강점·약점/히스토리/Footer 2버튼 — 또는 일러스트/추천칩/진행점/
   Footer 2버튼)는 그대로 유지하면서 톤만 새로 입혀 주세요.
4. 오행 5색(§4-2)과 점수 밴드 4단계 색(85+/70+/55+/~54, §3-10-2 참고)은 전 화면에서
   일관되게 쓰이므로, 새 팔레트를 제안하실 때 이 두 체계를 먼저 정의해 주시면
   편합니다.
5. 시안 전달 시 **화면 간 이동 흐름(어떤 버튼을 누르면 어디로 가는지)**을 명시해
   주시면 현재 네비게이션 구조를 그대로 유지하면서 화면만 교체하겠습니다.
6. 직접입력(DIRECT) vs 초대장(INVITE) 두 경로가 "세부 카테고리 선택" 이후부터
   갈라진다는 점(§2 표)을 감안해, 두 경로의 다음 화면(직접 입력 폼 / 초대장 생성
   화면)을 각각 별도 시안으로 준비해 주세요.
