## F. 서버-클라이언트 교차 의존성 발견 (신규)

| 항목 | 서버측(admin_web) | 클라이언트측(flutter_app) | 분석 |
|---|---|---|---|
| wishroom 캐릭터 소유 검증 | B-3: `wish-rooms/route.ts` POST에 검증 없음(미반영) | E: `afdde4d` 등 클라이언트 경쟁조건 완화는 있으나 서버 미검증 보완 못함 | 서버 미반영이 더 근본적 — **서버 수정이 우선**. 클라이언트 변경과 무관하게 서버 단독 반영 가능 |
| 신고 조작 방지 | B-3: `reports/route.ts`에 1인1회 제한 없음 | 해당 클라이언트 변경 없음(서버 전용 이슈) | 서버 단독 반영 가능 |
| 사주 결제 우회 방어 | B-2: `interpret/route.ts`에 콘텐츠 바인딩 검증 없음 | 클라이언트(`saju_renewal_api.dart`)는 `transaction_id`를 서버에 정상 전달 중 — 클라이언트는 문제 없음 | **서버 단독 수정 필요**, 클라이언트 변경 불필요 |

**결론**: B-2, B-3에서 발견된 3가지 보안 미반영 건은 **모두 admin_web(서버) 단독으로 cherry-pick 적용 가능**하며 flutter_app 쪽 변경을 요구하지 않음. 의존성 리스크 낮음 — 반영 결정만 하면 즉시 적용 가능.
