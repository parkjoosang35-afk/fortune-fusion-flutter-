# 귀인지도(Guinji Map) 현재 구조 — 디자이너 전달용

> 작성일: 2026-12 · 작성 목적: 디자인 리뉴얼 작업을 위해 "지금 코드가 실제로 어떻게
> 동작하는지"를 빠짐없이 정리합니다. 디자인 시안을 만드실 때 이 문서의 **화면 목록 /
> 흐름 / 데이터 구조**를 기준으로 삼아 주시면, 저(개발)는 그 시안을 받아 기존 로직
> (API·엔진·결제·공유)은 그대로 둔 채 화면(UI)만 새로 입혀 구현합니다.

## 0. 한눈에 보는 서비스 개념

**귀인지도**는 "내 생년월일로 지도를 만들고, 지인을 초대해서 그 사람과 나의 관계유형을
하나씩 지도에 채워가는" 서비스입니다.

- **호스트**(지도를 만든 사람): 초대장을 보내고, 자기 지도에 채워진 관계들을 보고,
  궁금한 관계는 **결제해서** 10장 심층 풀이를 봅니다. 결제·공유의 유일한 주체입니다.
- **게스트**(초대받은 사람): 링크를 열고 생년월일만 입력하면 "당신은 OO님에게 어떤
  존재인지" **간단한 결과 1개**를 무료로 봅니다. 결제 기능이 없고, 1회성 방문자입니다.
  게스트가 "나도 내 지도 만들기"를 누르면 그건 완전히 별개의 새 호스트 여정이 시작됩니다.

```
[호스트] 지도 생성 → 초대장 발송 ─┐
                                 ▼
                  [게스트] 링크 열기 → 생년월일 입력 → 간단 결과 1개(무료, 끝)
                                 │
                                 └─(선택) "내 지도 만들기" → 완전히 새로운 호스트 여정
                  ↓ (게스트가 입력을 완료하면 서버에 관계가 저장됨)
[호스트] 자기 지도에 새 관계가 채워짐 → 해당 인물 탭 → 결제(3가지 수단) → 10장 심층 풀이
                                 → 공유하기/저장하기(카카오·이미지)
```

## 1. 관계유형 체계 (V2, 6종 — 전 화면 공통)

| 코드 | 이름 | 한자 | 카테고리 | 한 줄 설명 |
|---|---|---|---|---|
| `CHEON_GWII` | 천생귀인 | 貴 | 귀인(boost) | 타고난 인연으로 서로를 살리고 크게 이끌어 주는 관계 |
| `SANG_SAENG` | 상생동행 | 生 | 귀인(boost) | 한쪽이 다른 쪽을 살리고 키워주는 상생의 관계 |
| `HAP` | 인연합 | 緣 | 인연(path) | 일지가 합을 이루어 자연스럽게 끌리고 정이 깊어지는 관계 |
| `BI_HWA` | 동류동반 | 比 | 인연(path) | 같은 오행으로 결이 비슷해 편안하게 동행하는 관계 |
| `SANG_GEUK` | 상극조율 | 剋 | 조율(care) | 서로 극하는 기운으로 긴장과 조율이 공존하는 관계 |
| `CHUNG` | 충돌극복 | 沖 | 조율(care) | 일지가 충하여 부딪히지만 그만큼 성장을 만드는 관계 |

- **3대 카테고리**: 귀인(boost) · 인연(path) · 조율(care) — 6종을 2개씩 묶음. 랭킹
  화면 필터, 결과 카드 집계 등 여러 화면에서 이 분류를 재사용합니다.
- 서버가 관계를 판정해서 코드값을 내려주고, 클라이언트는 **판정하지 않고 표시만** 합니다.
- 이름/생년월일 등 개인정보는 공유 콘텐츠(카카오 피드, 결과 카드 이미지)에 **절대 넣지
  않습니다** — 집계된 인원수·관계유형만 노출(비식별 원칙).

## 3. 핵심 화면 상세 (디자인 참고용)

### 3-1. 지도 메인 (`/guinji-map/m`)
- 상단: "{이름}님의 귀인 지도", 공유 버튼
- "N명과 연결되어 있어요" + 지인 직접 추가 버튼 + 랭킹 버튼 + 초대 버튼
- (내 사주 계산 결과가 있으면) 나는 어떤 사람인지 카드
- **관계 그래프**: 중심(나) 기준 방사형 배치, 사진 노드, 같은 유형끼리 그물망 선,
  회전 궤도·펄스 애니메이션. 사람이 없으면 "링크를 받은 지인이 생년월일을 입력하면
  이곳에 한 명씩 연결돼요" 안내
- 참여한 유형만 필터 칩으로 노출 → 탭하면 그래프에서 해당 유형만 강조
- 참여자 3명 미만이면 안내 배너
- 상위 3명 "가장 강한 인연" 리스트 + 전체보기
- 하단 "친구 초대하고 지도 완성하기" CTA

### 3-2. 인물 시트 (노드 탭 시)
- 캐릭터 상반신, 이름, 관계유형 인장
- 해금 전: 결제 유도 / 해금 후: "열어 둔 풀이 바로 보기"로 바로 이동
- CTA 2개: 더보기(관계상세) / 공유하기

### 3-3. 결제 분기 (관계 상세 → 미해금 시)
3가지 선택지:
1. **프리패스로 보기** — 보유 수량 차감
2. **복주머니로 보기** — 포인트(재화) 차감
3. **광고 보고 무료로 보기** — 리워드 광고 시청 후 무료 해금

해금 성공 시에만 서버 상태가 바뀌고, 실패하면 시트를 유지한 채 토스트 안내.

### 3-4. 10장 심층 풀이
결제(또는 광고 시청) 완료 후 보여지는 10장짜리 상세 풀이. 하단에 "결과 공유하기"로
카카오/이미지 공유.

### 3-5. 초대 시트 (`/guinji-map/m/share`)
- 카카오톡 공유(전용 피드 카드) + "더보기"(OS 공유시트)
- 우상단 "⋯" → 링크 관리 패널(새 링크 발급 / 공유 중단 / 다시 켜기 / 현재 상태 표시)

### 3-6. 랭킹 / 유형별 목록 (`/guinji-map/m/ranking`)
- 탭1 "케미 랭킹": 점수 내림차순 포디움 + 리스트, "결과 카드로 공유하기" CTA
- 탭2 "유형별 목록": 전체 + 6종 필터 칩, 유형별로 그룹 묶어 표시. "⋯" → 삭제 확인
  다이얼로그("OO님을 지도에서 뺄까요 / 관계 결과와 열어 둔 풀이도 함께 사라져요")

### 3-7. 결과 카드 (공유용 이미지, `guinji_result_card_screen.dart`)
- 세로 3:4 카드: "{이름}의 지도에는 소중한 인연 N명", 카테고리별(귀인/인연/조율)
  인원 집계, 가장 많은 유형의 한 줄 설명을 인용구로 표시
- 이름 비공개 원칙 — 숫자·유형 집계만 표시
- 버튼: 이미지로 저장 / 공유하기(OS 공유시트) / 카카오톡으로 지도 자랑하기(전용)

### 3-8. 게스트 참여 → 결과
- 참여: 초대한 사람 이름 노출, 게스트 본인 생년월일만 입력해 제출(로그인 필요, 참여 시 포인트 지급)
- 결과: "당신은 {호스트}님에게 {유형}이에요" + 점수 + 근거 3줄 + 두 얼굴
- 하단에 "10장 풀이 미리보기"(1장 맛보기 + 2~10장 제목만 잠금 형태로 나열) — **결제 기능
  아님**, "내 지도를 만들면 이런 깊은 풀이를 가질 수 있어요"라는 광고/유도 문구와 버튼만 있음
- 버튼: 나도 내 귀인지도 만들기(완전 별개의 새 여정) / 결과 공유하기
- **자동 화면 전환 금지** — 모든 이동은 사용자가 버튼을 눌러야만 발생

## 6. 데이터/상태 (디자인 시 참고 — 실제 값 예시)

- 호스트의 지도 1개 = `mapId`, `mapToken`(공유 링크용), `name`(지도 이름/소유자 이름)
- 참여자(= 지도에 채워진 사람) 1명 = `GuinjiPerson`: id, 이름, 생년월일, 오행, **관계유형
  코드(6종 중 1개)**, 케미 점수(0~100), 노트
- 관계유형은 서버가 판정해서 내려줌 — 클라이언트는 표시만

## 7. 변경 금지 / 재사용해야 하는 로직 (디자인 변경과 무관하게 유지)

디자인을 새로 입혀도 아래 로직·API·동작은 **그대로 유지**됩니다(디자이너가 몰라도 되지만,
혹시 플로우를 다시 그리실 때 참고):

- 딥링크 구조, 결제 3분기(프리패스/복주머니/광고), 삭제 확인 플로우
- 비식별 원칙(공유 콘텐츠에 이름/생년월일 노출 금지)
- 게스트 결과화면 "자동 전환 금지" — 버튼을 눌러야만 다음 화면으로 이동

## 9. 디자이너에게 드리는 요청

1. 위 2장의 **화면 목록(2-1, 2-2)** 순서대로 시안을 만들어 주세요(신버전 `/guinji-map/*`
   계열만 해당 — 2-4 구버전은 제외).
2. 각 화면 시안에 **어떤 텍스트가 동적으로 바뀌는지**(이름, 숫자, 관계유형 등) 표시해
   주시면 좋습니다 — 위 4~6장 데이터 구조를 참고해 주세요.
3. 관계유형 6종 색상/아이콘(한자 인장 포함)을 통일된 톤으로 정의해 주시면, 전 화면에
   일괄 적용하겠습니다.
4. 결제 3분기 UI(프리패스/복주머니/광고)는 꼭 포함해 주세요 — 로직은 이미 있어서 UI만
   새로 입히면 됩니다.
5. 시안 전달 시 **화면 간 이동 흐름(어떤 버튼을 누르면 어디로 가는지)**을 명시해 주시면
   라우팅 그대로 유지하면서 화면만 교체하겠습니다.

> 저는 받은 시안을 코드로 정확히 옮기는 데 집중하겠습니다. 로직(API 연동, 결제 분기,
> 공유, 삭제 등)은 기존 그대로 재사용하고 화면(UI)만 새 디자인으로 교체합니다.
